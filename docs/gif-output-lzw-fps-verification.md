# GIF出力修正・FPS3段階検証記録

## 不具合の原因

旧GIFはGIF89aヘッダー、3フレーム、フレーム遅延を含んでいたが、標準デコーダで`broken data stream when reading image file`となった。大画像のLZWストリームで、辞書のコード幅を増やす時点がデコーダとずれ、9ビットから10ビット以上へ移行した後のビット列が誤読されていた。

修正後は、GIF89a LZWの出力後コード幅遷移、辞書上限、Clearコードによる辞書リセットを既知の互換実装と同じ順序へ揃えた。これにより、コード幅拡張をまたぐ大きなフレームでもストリームが途中終了しない。

| 項目 | 旧出力 | 修正後 |
| --- | --- | --- |
| 実ファイルの再生 | Pillow標準デコーダで`broken data stream` | 3フレームを正常に読込可能 |
| 2×GIFの解像度 | 2344×1232px | 2344×1232px |
| 8fps設定の遅延 | 期待値125ms | GIFの1/100秒単位により130ms（13cs） |
| アニメーション | 途中で壊れる | 3フレーム・ループ再生 |

## FPS選択

出力ダイアログでは、通常のGIF89a遅延単位（1/100秒）に対応した次の3段階を提供する。

| 選択 | 指定遅延 | GIF保存値 | 用途 |
| --- | ---: | ---: | --- |
| 低（4fps） | 250ms | 25cs | どっとアニメ調 |
| 中（8fps） | 125ms | 13cs（130ms） | なめらか。既定値 |
| 高（12fps） | 83ms | 8cs（80ms） | 最もなめらか |

同じ遅延値はAPNGにも渡す。アイコンアニメーションが無効な場合は、従来どおり静止1フレームとして出力する。

## 検証結果

| 観点 | 結果 |
| --- | --- |
| LZW回帰 | 大画像の全ピクセル復元、GIF89aフレーム、3段階遅延を自動テストで確認 |
| 実GIF | 2×、中（8fps）で生成。PillowがGIF・2344×1232px・3フレーム・各130ms・アニメーションありとして読込成功 |
| UI（PC） | GIFダイアログに低・中・高の3段階を表示し、中を選んだ保存通知が`8FPS`となることを確認 |
| UI（390px相当） | ダイアログ358px幅、FPSボタン各101×37px、横オーバーフローなし。`gif-lzw-fps-mobile.png`で確認 |
| 既存回帰 | GIF/APNG、自由変形、背景画像の全20件が成功。ブラウザにはReact DevTools案内とBabel開発版警告以外の実行時エラーなし |
